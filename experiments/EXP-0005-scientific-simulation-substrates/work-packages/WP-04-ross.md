**Critical complexity / highest-risk WP.** Requires independent theoretical design and WP-00 oracle; separate small feasibility PR before performance. **Owned:** EXP-0005/backends/ross/, tests/ross/, configs/ross/, compact runs/ross/.

## Required **independent causality statement before coding**
Propose LP state S=(V,last_t,refractory_until,synapse traces,counter,RNG state or its reversible stream) and event E=(timestamp,id,source,weight,delay). Define deterministic tie policy and forward transition F_E(S), reverse R_E such that R_E(F_E(S))=S in exact stored representation for each event, with replay F_E(R_E(F_E(S)))=F_E(S). If floats cannot reverse arithmetically, use exact before-image state in event message or logged checkpoint and explicitly charge its bytes; don't assert subtraction inverses floating-point addition. Each emission must be cancelled via ROSS rollback / anti-message; no irreversible observer output until event committed past GVT. For stochastic events ensure RNG restoration exact using supported ROSS reversible RNG protocol. State which operations are not locally reversible (global plasticity shared across LPs, external I/O); postpone those. Explain who owns synaptic plastic state and message timestamps to avoid cross-LP data races. Demonstrate positive lookahead assumptions of conservative baseline; Time Warp may handle out-of-order arrivals but must NOT change event-time causality semantics.

Instrument positive rollback count, reversed state and cancelled/re-emitted children, independent chronological oracle's **committed trace**. Use '--synch=6' version-supported sequential rollback-check and '--synch=4' debug for reversibility; failure is NO-GO. Merely setting --synch=3 with 0 rollbacks is NOT a proof.
D. Commit separate correctness PR for 2-LP then 128 LP, no 10k benchmark yet; independent reviewer inspects forward/reverse and committed-output handling including RNG and timestamps.
E. Only after GO, run W=1/2/4/6 ranks and N=128/1024/10k, disconnected vs random/modular/bursty plus short recurrent feedback under small memory cap. Record processed, committed, rolled back, reexecuted, GVT cycles, max speculative event backlog, RSS, output trace accuracy, wall time, bottlenecks; compare sequential and ROSS native conservative, and EXP-0004 separately by compatible semantics. Test rollback storm with explicit bound and stop.

## Acceptance / invalid shortcuts
No 'optimistic scheduler' hand-coded outside ROSS relabeled as backend. No mutable shared cross-LP state without versioned synchronization. No non-GVT committed output counted. No reverse handler that only undoes neuron V while failing to restore last_t/refractory/RNG/generated children. No equal event-rate claim if most events are discarded by rollback. If no safe forced rollback can be produced, deliver honest inconclusive/NO-GO and preserve logs. A theoretically correct conservative baseline with positive lookahead is valid but not an optimistic result.
